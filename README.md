# บาร์ลับ POS (Next.js + Supabase)

ระบบสั่งอาหารประจำโต๊ะสำหรับร้านเหล้า/สโลว์บาร์ ธีมวินเทจ ใช้ Supabase เป็นฐานข้อมูล
ลูกค้าสแกน QR ประจำโต๊ะเพื่อเปิดเมนูและสั่งได้ พร้อมระบบหลังร้านสำหรับจัดการเมนู/โต๊ะ/ออเดอร์/รีวิว

## ฟีเจอร์

- เมนูแบบการ์ด 4 คอลัมน์บนจอใหญ่ 3 คอลัมน์บนแท็บเล็ต 2 คอลัมน์บนมือถือ
- แตะการ์ดเพื่อเพิ่มลงบิลได้ทันที ปรับจำนวนได้ที่แถบล่างหรือในบิล
- **ช่องค้นหาเมนู** พิมพ์แล้วกรองทันที และขึ้นตัวเลขข้างชื่อหมวดว่าหมวดนั้นเจอกี่รายการ
- **ของหมดยังโชว์อยู่** ปิดสวิตช์เมนูในหลังร้าน = ของหมด ลูกค้ายังเห็นว่าร้านมีอะไร แค่กดสั่งไม่ได้
  (การ์ดจะหม่นลงและขึ้นป้าย "ของหมด" · ถ้าของหมดหลังใส่บิลไปแล้ว ปุ่มสั่งจะล็อกจนกว่าจะเอาออก)
- **หมวดเมนูแก้ได้เอง** ตั้งต้นมี เครื่องดื่ม / เหล้า / เบียร์ / อาหาร / ของทานเล่น · Manager เพิ่ม เปลี่ยนชื่อ ลบ และจัดลำดับได้ที่ ตั้งค่าร้าน → หมวดหมู่
  เปลี่ยนชื่อหมวดแล้วเมนูย้ายตามให้เอง ลบหมวดแล้วเมนูที่ค้างจะถูกย้ายไปหมวดแรก ไม่มีเมนูไหนหายไป
  **หนึ่งเมนูอยู่ได้หลายหมวดพร้อมกัน** (เช่น ปีกไก่ทอด โผล่ทั้ง "ของทานเล่น" และ "อาหาร") จัดลำดับการแสดงได้เอง
- **หลังร้านแก้ไว้ก่อน กดบันทึกทีเดียว** ทั้งแท็บ **เมนู** · **ของเล่น** · **สต็อก (ตัวสินค้า)**
  เพิ่มใหม่ แก้ไข และ**ลบ** ล้วนพักไว้บนจอก่อน · แถวที่สั่งลบจะจางลงพร้อมป้าย "จะลบ" และปุ่ม **เอากลับ** กดผิดแล้วกู้ทัน
  กด **บันทึกทั้งหมด** ทีเดียวลงจริงหมด · ยิงคำขอเดียวต่อหนึ่งครั้งที่กด (เดิมวนยิงทีละรายการ 20 เมนู = 20 รอบ ช้ามากบนเน็ตมือถือ)
  · ยังไม่ได้บันทึกแล้ว**เปลี่ยนแท็บหรือปิดเว็บ ระบบเตือนก่อนเสมอ** เพราะของพวกนี้อยู่แต่ในหน่วยความจำ ปิดแล้วหายจริง
  · **ยกเว้น เติมของ / ตัดของ / นับใหม่ ในแท็บสต็อก ยังบันทึกทันที** เพราะเป็นงานหน้าร้านที่ต้องลงเดี๋ยวนั้น และมีเงินเข้าบัญชีไปด้วย
- **เมนูย่อย (กลุ่มตัวเลือก)** บางเมนูต้องให้ลูกค้าเลือกเพิ่มก่อนสั่ง เช่น กาแฟต้องเลือกไซซ์ แล้วค่อยเลือกท็อปปิ้ง
  หนึ่งเมนูมีได้หลายกลุ่ม · ตัวเลือกในกลุ่ม **เลือกจากเมนูที่มีอยู่แล้ว** ไม่ได้สร้างของใหม่ซ้อน
  ราคาที่ตั้งคือ **ค่าเพิ่ม** ที่บวกทับราคาเมนูหลัก ตั้งแยกจากราคาขายเดี่ยวได้ (ช็อตเอสเพรสโซขายเดี่ยว 45 แต่เติมใส่แก้วอื่นคิด 20)
  แต่ละกลุ่มตั้งได้ว่าต้องเลือกอย่างน้อยกี่ชิ้นและสูงสุดกี่ชิ้น (**นับเป็นจำนวนชิ้นรวม** ไม่ใช่จำนวนชนิด)
  กลุ่มที่เลือกได้อย่างเดียวขึ้นเป็นปุ่มกดเลือก · กลุ่มที่เลือกได้หลายชิ้นขึ้นเป็นปุ่ม + −
  เมนูเดียวกันที่เลือกคนละชุด = คนละบรรทัดในบิล · ราคาคิดที่เซิร์ฟเวอร์เสมอ เหมือนราคาเมนูปกติ
- **เก็บเงินได้จากคิว "ต้องทำ" เลย** แตะกล่องแล้วเลือก เสร็จ·เก็บเงินสด / เสร็จ·เก็บเงินโอน / เสร็จ·ยังไม่เก็บเงิน
  สองปุ่มแรกปิดบิลเป็น "จ่ายแล้ว" ทีเดียวจบ **ยอดขายเข้า Dashboard ทันที** และสต็อกถูกตัดไปพร้อมกัน
  เลือก "ยังไม่เก็บเงิน" ถ้าเปิดบิลค้างไว้ก่อน แล้วไปเก็บทีหลังที่แท็บออเดอร์เหมือนเดิม
  · **ยอดขายนับเฉพาะบิลที่ปิดเป็น "จ่ายแล้ว"** บิลที่แค่เสิร์ฟยังไม่นับ (เงินยังไม่เข้าร้านจริง)
  · ยอดขายจากออเดอร์ขึ้นที่ **บัญชี → Dashboard** ไม่ไปโผล่ในหน้า "บันทึกรายรับจ่าย" ซึ่งเป็นสมุดที่กรอกมือ
- **บิลเดี่ยว** ปุ่มอยู่ข้างปุ่มรีเฟรชในแท็บ **ต้องทำ** · สำหรับลูกค้าที่ไม่ได้นั่งโต๊ะ
  เลือกจากเมนูที่มี หรือ**พิมพ์รายการที่ไม่มีในเมนู**เอง (ชื่อ + ราคา) · ส่งแล้วเข้าคิว "ต้องทำ" ชื่อ **ลูกค้าหน้าร้าน**
  แล้วกดเรียบร้อย/เก็บเงินที่เดิม ยอดเข้าสรุปรายวันเส้นทางเดียวกับออเดอร์ของโต๊ะ
  รายการนอกเมนูรับได้เฉพาะคำขอที่มีโทเคนพนักงาน (เป็นทางเดียวในระบบที่ราคามาจากฝั่ง client)
- **สต็อก** แท็บแยก **ใช้ได้ทุก role** · ดู เติมของ ตัดของ นับใหม่ ได้ทุกคน (งานหน้าร้าน) ส่วนเพิ่ม/แก้/ลบตัวสินค้าเป็นของ Manager
  แต่ละเมนูผูกกับสินค้าในสต็อกได้**หลายตัว ตั้งจำนวนแยกกัน** (โอลด์แฟชั่น 1 แก้ว = เบอร์บอน 45 มล. + น้ำตาล 10 มล. + เชอร์รี่ 1 ลูก)
  ใส่ทศนิยมได้ เพราะของจริงตัดจากหน่วยใหญ่ · เมนูย่อยก็ตัดสต็อกของตัวเองด้วย
  **ตัดตอนกด "เรียบร้อย"** (จังหวะที่ของถูกยกออกจากบาร์จริง) · ยกเลิกก่อนเสิร์ฟ = ไม่ตัด · กดรัวสองทีก็ตัดครั้งเดียว
  **เตือนตอนใกล้หมด ปิดเมนูตอนหมด** — สต็อกไม่พอ ลูกค้าเห็นเป็น "ของหมด" ทันที แต่ไม่ไปทับสวิตช์ที่เจ้าของร้านตั้งไว้
  ทุกการเข้าออกเก็บประวัติไว้ (ใคร เมื่อไหร่ เหลือเท่าไหร่ จากออเดอร์ใบไหน)
  · **เติมของแล้วลงบัญชีให้เลย** กรอก "จ่ายไปเท่าไหร่" + เงินสด/โอน + หมวดบัญชี ตอนรับของ
  ระบบจะลงเป็นรายจ่ายในสมุดของวันนั้นให้ ไม่ต้องไปกรอกซ้ำที่แท็บบัญชี · เว้นว่างไว้ = ไม่ลงบัญชี
  **ช่องเงินเห็นเฉพาะ Manager** ด้วยเหตุผลเดียวกับที่สมุดบัญชีปิดจากพนักงานหน้าร้านมาแต่ต้น
  (พนักงานยังเติมของได้ตามปกติ แค่ไม่ได้กรอกราคา)
- **รูปเมนูกับของเล่นถ่ายจากมือถือได้เลย** ตอนเพิ่ม/แก้รายการมีปุ่ม **ถ่ายรูป** (เปิดกล้องหลังทันทีบนมือถือ) และ **เลือกจากเครื่อง**
  รูปถูกย่อในเครื่องก่อนส่งเสมอ (ด้านยาว 1200px, jpeg) รูปกล้อง 5-8 MB จะเหลือราว 150-300 KB · อัปโหลดขึ้น Supabase Storage แล้วเก็บแค่ลิงก์ลงฐานข้อมูล
  ไฟล์ HEIC ของ iPhone ใช้ได้เพราะแปลงเป็น jpeg ตั้งแต่ในเครื่อง · ยังวางลิงก์รูปเองได้เหมือนเดิมที่ปุ่ม **ใส่ลิงก์แทน**
- สั่งได้เฉพาะเมื่อสแกน QR ประจำโต๊ะ (`/?table=คีย์ลับ` ที่ระบบสุ่มให้) ถ้าเข้าหน้าหลักจะกดสั่งไม่ได้ ต้องสแกนก่อน
- **โต๊ะจำไว้ 15 นาที** นับใหม่ทุกครั้งที่ลูกค้าแตะเมนู/สั่งของ นั่งนานแค่ไหนก็ไม่โดนเตะ
  จะหลุดก็ต่อเมื่อวางเครื่องทิ้งไว้เกิน 15 นาที
- **แตะที่ชื่อโต๊ะมุมขวาบน** เพื่อออกจากโต๊ะแล้วไปสแกนโต๊ะใหม่ ถ้ายังไม่มีโต๊ะ แตะแล้วเปิดกล้องสแกนได้เลย
- **ปุ่มเรียกพนักงาน** โผล่บนหน้าลูกค้าหลังสแกนโต๊ะแล้ว กดแล้วเด้งแจ้งเตือนหาพนักงานทุกคนพร้อมชื่อโต๊ะ
  กดซ้ำภายในนาทีเดียวจะไม่สร้างใบซ้อน และปุ่มจะค้างสถานะ "เรียกแล้ว" ไว้ 2 นาที
- **แท็บของเล่น (ฝั่งลูกค้า)** เห็นรูปกับชื่อ กดได้แค่ดูรูปใหญ่ สั่งซื้อ/จองผ่านเว็บไม่ได้ ต้องติดต่อพนักงานที่บาร์
  ชิ้นที่มีคนใช้อยู่จะขึ้นป้ายมุมภาพและภาพหม่นลง
- แท็บรีวิว พิมพ์ติชมแล้วบันทึกลงฐานข้อมูล · **ขึ้นหน้าเว็บโชว์ได้เฉพาะรีวิวที่ Manager กดอนุมัติแล้ว**
- **เว็บพนักงานแยกที่ `/staff`** เข้าด้วยการเลือกชื่อตัวเองแล้วใส่ PIN 6 หลัก (ไม่มีประตูลับ/รหัสผ่านหลังร้านแบบเดิมแล้ว)
- **ใส่ PIN พิมพ์จากคีย์บอร์ดก็ได้** ไม่ต้องจิ้มปุ่มบนจออย่างเดียว (Backspace = ลบ, Esc = ย้อนกลับ)
- **แท็บ "ต้องทำ" (Dashboard)** พนักงานทุกคนเห็น · รวมออเดอร์ใหม่กับใบเรียกพนักงานไว้ที่เดียว เรียงจากที่รอนานสุด
  แตะกล่องแล้วเลือก เรียบร้อย/ยกเลิก (ปุ่มใหญ่เต็มความกว้าง เขียว/แดง กดด้วยนิ้วโป้งข้างเดียวได้) กล่องหายทันทีแล้วค่อยบันทึกเบื้องหลัง ไม่ต้องยืนรอ
  · **เตือนด้วยการกระพริบตามความด่วน** กล่องไล่จากทอง → ส้ม (กระพริบทุก 2 วิ) → แดง (ทุก 0.9 วิ) และ**ทั้งหน้าเว็บสว่างวูบเป็นจังหวะ**ตามงานที่ด่วนที่สุด
    เกณฑ์อยู่ที่ `lib/urgency.js` ที่เดียว: ออเดอร์ใหม่ 3/8 นาที · ใบเรียกพนักงานด่วนกว่าเท่าตัว (1.5/4 นาที) เพราะลูกค้านั่งรออยู่ที่โต๊ะจริง ๆ
    ทั้งหน้ากระพริบตั้งแต่มีงานค้างใบแรกและกระพริบต่อแม้เปิดค้างอยู่แท็บอื่น (คิวงานดึงที่หน้าหลักที่เดียวผ่าน `lib/use-todo-queue.js`)
    เครื่องที่ตั้งค่าระบบว่าไม่เอาภาพเคลื่อนไหว (`prefers-reduced-motion`) จะได้แสงค้างไว้แทนการกระพริบ
  · **อัปเดตพร้อมกันทุกเครื่องแบบทันที** ใครกดปิดงานไป เครื่องอื่นเห็นทันทีโดยไม่ต้องรีเฟรช (ดูหัวข้อ Realtime ข้างล่าง)
  · สองคนกดใบเดียวกันพร้อมกันไม่ทำให้สถานะตีกัน คนที่มาทีหลังจะได้ข้อความว่ามีคนจัดการไปแล้ว
  · ระหว่างบันทึกจะมีแถบ "กำลังบันทึก" ข้างบน และกันไม่ให้ปิดหน้าหรือออกจากระบบจนกว่าจะบันทึกเสร็จ
- **แท็บของเล่น (ฝั่งพนักงาน)** พนักงานทุกคนสลับสถานะ มีคนใช้อยู่ ↔ ว่าง ได้ พร้อมระบุว่าโต๊ะไหนเอาไปใช้
- **เปลี่ยน PIN ของตัวเองได้** ปุ่ม **เปลี่ยนรหัส** อยู่ข้าง ๆ ปุ่มออกจากระบบ · ต้องใส่ PIN เดิมด้วยทุกครั้ง
  (เครื่องหน้าร้านมักเปิดค้างไว้ ใครเดินมาหยิบไปกดก็เปลี่ยน PIN ของเจ้าของเครื่องได้เลยถ้าไม่ถาม)
  เปลี่ยนแล้วเครื่องอื่นที่ค้างอยู่ในระบบจะหลุด ส่วนเครื่องที่กำลังกดใช้ต่อได้เลย
- **เจ้าของร้านกดดู PIN ของพนักงานได้** ที่แท็บพนักงาน มีปุ่ม **ดู PIN** รายคน ไว้ใช้ตอนมีคนลืม
  · เก็บสำเนา PIN แบบเข้ารหัส (AES-256-GCM) ด้วยกุญแจที่อยู่ใน env `PIN_SECRET` ซึ่งไม่ได้อยู่ในฐานข้อมูล
  ฐานข้อมูลหลุดไปอย่างเดียวจึงยังเปิดอ่านไม่ได้ · ตัวที่ใช้ตรวจตอนล็อกอินยังเป็น hash เหมือนเดิม
  · ต้องกดขอทีละคน ไม่ได้ส่งมาพร้อมรายชื่อ และทุกครั้งที่กดดูจะลงบันทึกว่าใครดู PIN ของใครเมื่อไหร่
  · ไม่ตั้ง `PIN_SECRET` = ไม่เก็บสำเนาเลย ระบบทำงานปกติทุกอย่าง แค่ปุ่มดู PIN ใช้ไม่ได้
- **แท็บออเดอร์เป็นของ Manager คนเดียว** (เป็นเรื่องยอดขาย) · หน้างานของ Staff ใช้แท็บ "ต้องทำ" แทน
- **ของที่เจ้าของร้านเห็นคนเดียว** ตั้งชื่อบัญชีไว้ที่ `OWNER_NAME` ใน `lib/staff.js` (ตอนนี้คือ **ดุ่ย**) ได้แก่
  แท็บ **พนักงาน** · แท็บ **บันทึก** · ตั้งค่าร้าน → **โต๊ะ + QR** (ออกคีย์ใหม่ทีเดียว QR ที่แปะไว้หน้าร้านใช้ไม่ได้ทั้งหมด)
  และ แจ้งเตือน → **เตือนออเดอร์ค้าง** (เป็นค่าของทั้งร้าน ตั้งครั้งเดียวมีผลกับทุกคน)
  ล็อกที่ฝั่งเซิร์ฟเวอร์ด้วย ไม่ใช่แค่ซ่อนปุ่ม · Manager คนอื่นยังเห็น ออเดอร์ / บัญชี / ตั้งค่าร้าน (เมนู หมวดหมู่ หมวดบัญชี ของเล่น รีวิว) ตามเดิม
  ⚠️ ถ้าเปลี่ยนชื่อบัญชีในระบบ ต้องมาแก้ `OWNER_NAME` ตามด้วย · ถ้าในร้านไม่มี Manager ที่ชื่อตรงกับค่านี้เลย
  ระบบจะถือว่า Manager ทุกคนเป็นเจ้าของไปก่อน (กันร้านล็อกตัวเองจนไม่เหลือใครเข้าแท็บพนักงานได้)
- **ซ่อนแท็บแจ้งเตือนรายคนได้** เครื่องไหนตั้งค่าเสร็จแล้วก็ไม่ต้องเห็นแท็บนั้นอีก · เจ้าของร้านกดได้ที่
  แจ้งเตือน → เครื่องที่เปิดรับอยู่ (ทั้งร้าน) → **ซ่อนแท็บแจ้งเตือน** · ซ่อนเป็นรายคน (มีผลทุกเครื่องของเขา)
  แท็บจะกลับมาเองถ้าเครื่องของคนนั้นหลุดจากระบบแจ้งเตือนจนหมด ไม่งั้นจะเปิดแจ้งเตือนใหม่ไม่ได้เลยตลอดกาล
  · เก็บใน `settings` key `notify_tab_hidden` จึงไม่ต้องแก้ schema
- หลังร้าน (อยู่ใน `/staff` ฝั่ง Manager): จัดการเมนู, หมวดหมู่เมนู, หมวดบัญชี, ของเล่น, โต๊ะ + สร้าง QR ให้เซฟไปพิมพ์ได้เลย, ดูรีวิว
- **ผังร้านแบบแตะได้**: โต๊ะเปลี่ยนสีตามสถานะ (ว่าง / มีคนนั่ง / สั่งแล้ว / จอง) · ต่อโต๊ะให้คิดรวมเป็นบิลเดียว · ย้ายลูกค้าไปโต๊ะอื่นพร้อมบิล
  · พนักงานทุกคนดูผังได้ แต่แก้ผังได้เฉพาะ Manager (ลากวางได้ทั้งโต๊ะ กำแพง บาร์ และป้ายข้อความ)
  · จุดจับปรับขนาดแยกสองจุด: **ขอบขวา = ยืดยาว** และ **ขอบล่าง = ปรับความหนา** กำแพงจึงยืดยาวได้โดยไม่หนาขึ้นตาม
  · **ลากโต๊ะไปชิดกันแล้วระบบถามว่ารวมเป็นโต๊ะเดียวไหม** ตอบตกลงแล้วจะวาดเป็นก้อนเดียว ใช้ชื่อโต๊ะหลัก และบิลที่ยังไม่จ่ายไปรวมกัน
    ถามทุกครั้ง ไม่รวมให้เองเงียบ ๆ · แยกคืนได้ทั้งในโหมดแก้ไขผัง (ปุ่ม **แยกโต๊ะที่เลือก**) และหน้างาน (แตะโต๊ะ → **แยกโต๊ะออก**)
  · **ปุ่มย้อนกลับ** ในโหมดแก้ไขผัง ถอยได้ทีละขั้น 40 ขั้น (นับการลากหนึ่งครั้งเป็นหนึ่งขั้น) และหายไปเมื่อออกจากโหมดแก้ไข
  · **★ ตั้งเป็นผังตั้งต้น / คืนผังตั้งต้น**: จำผังที่จัดไว้ตอนเปิดร้านได้หนึ่งชุด ระหว่างวันลากโต๊ะไปต่อกันตามลูกค้าได้ตามสบาย
    วันใหม่กดปุ่มเดียวคืนตำแหน่งโต๊ะ กำแพง และแยกโต๊ะที่ต่อกันไว้กลับหมด · เก็บใน `settings` key `floor_default` จึงไม่ต้องแก้ schema
- **ระบบเข้างาน/ออกงาน** พนักงานได้รับการแจ้งเตือนเฉพาะตอนอยู่ในกะ ส่วน Manager ได้รับตลอด (ปิดเองได้ต่อเครื่อง)
- **บันทึกการทำงานทุกอย่าง** ใครทำอะไรเมื่อไหร่ เก็บย้อนหลัง 3 เดือน แล้วลบให้อัตโนมัติ · ดูได้เฉพาะเจ้าของร้าน
- **แท็บเมนูหลังร้านแก้แบบรวบยอด**: กดปิด/เปิด กดแก้ไข หรือเลื่อนลำดับ จะยังไม่ยิงเซิร์ฟเวอร์ทันที
  แก้ให้ครบก่อนแล้วค่อยกด "บันทึกทั้งหมด" ทีเดียว (แก้ไขขึ้นเป็น pop-up ไม่ต้องเลื่อนไปกรอกข้างบน)
- สถานะออเดอร์: ใหม่ → เสิร์ฟแล้ว → จ่ายแล้ว (หรือยกเลิก) กดเปลี่ยนได้จากหน้าออเดอร์
  · **ตอนกด "จ่ายแล้ว" ต้องเลือกด้วยว่าลูกค้าจ่ายเงินสดหรือเงินโอน** เพราะ Dashboard บัญชีแยกยอดสองช่องนี้จากตรงนั้น
  · แท็บออเดอร์ดูเป็นรายวัน (ตั้งต้นคือวันนี้) เลือกวันย้อนหลังได้ หรือกด "ดูทุกวัน"
- **แท็บบัญชี (Manager เท่านั้น)** มีสองซับแท็บ
  · **บันทึกรายรับจ่าย** — กรอกวันที่ (ตั้งต้นวันนี้) ประเภท (รายรับ/รายจ่าย ตั้งต้นรายจ่าย) หมวดหมู่ รายการ เงินสด เงินโอน
    รวมเงินคิดให้เอง และหมายเหตุ · กด **+ เพิ่มรายการ** ต่อกันไปเรื่อย ๆ แล้วกดบันทึกทีเดียว
    (ถ้ามีแถวไหนกรอกไม่ครบ จะไม่บันทึกสักแถวและบอกว่าแถวที่เท่าไหร่ผิด จะได้ไม่ต้องเดาว่าอันไหนลงไปแล้ว)
    · ด้านล่างเป็น**ตาราง**รายการของเดือนที่เลือก (วันที่ ประเภท หมวดหมู่ รายการ เงินสด เงินโอน รวม หมายเหตุ ลงโดย)
    แถวเดียวจบต่อหนึ่งรายการ เห็นได้หลายสิบรายการโดยไม่ต้องเลื่อน · วันที่ขึ้นเฉพาะแถวแรกของแต่ละวันแล้วขีดเส้นคั่นไว้
    · กด **แก้ไข/ลบ** ได้จากในตาราง · เลื่อนดูเดือนก่อนหน้าได้
  · **Dashboard** — ภาพรวมช่วง 6/12/24 เดือน (ยอดขายรวม ต้นทุนสินค้า ค่าใช้จ่าย กำไรสุทธิ ยอดขายเงินสด ยอดขายเงินโอน)
    แล้วแยกเป็น **สรุปรายเดือน** (กราฟแท่ง + ตารางที่มีแถวรวมท้ายสุด) กับ **สรุปตามหมวดหมู่**
    (หมวดเป็นแถว เดือนเป็นคอลัมน์ ทุกหมวดมีสองแถว รายรับสีเขียว รายจ่ายสีแดง)
    · **ยอดขายรวม = ออเดอร์ที่ปิดเป็น "จ่ายแล้ว" + แถวประเภทรายรับที่กรอกเองในสมุด** (โชว์แยกให้เห็นว่ามาจากไหน จะได้จับได้ถ้ากรอกซ้ำ)
    · **กำไรสุทธิ = ยอดขาย − ต้นทุนสินค้า − ค่าใช้จ่าย** โดย "ต้นทุนสินค้า" คือรายจ่ายในหมวดที่ติ๊กไว้ว่าเป็นต้นทุน ที่เหลือนับเป็นค่าใช้จ่าย
- **หมวดบัญชีแก้ได้เอง** ที่ ตั้งค่าร้าน → **หมวดบัญชี** · ตั้งต้นมี เหล้า เบียร์ เครื่องดื่ม อาหาร น้ำแข็ง วัตถุดิบ ค่าแรง ค่าเช่า ค่าน้ำ ค่าไฟ
  การตลาด ขนส่ง อุปกรณ์ร้าน ซ่อมแซม ใบอนุญาต ค่าธรรมเนียม อื่น ๆ (หกหมวดแรกติ๊กเป็น **ต้นทุนสินค้า** ไว้ให้)
  เปลี่ยนชื่อหมวดแล้วรายการเก่าตามไปเอง · เอาหมวดออกจากรายชื่อแล้วรายการเก่ายังอยู่ครบและยังนับใน Dashboard เหมือนเดิม
  (ต่างจากหมวดเมนูตรงนี้ เพราะเป็นบัญชีย้อนหลัง ไปแก้ประวัติแล้วตัวเลขเดือนเก่าจะเปลี่ยนโดยไม่มีใครสั่ง)
- **แจ้งเตือนเข้ามือถือ (Web Push)** เด้งเตือนแม้ปิดแอปไปแล้ว ฟรี ไม่จำกัดจำนวนข้อความ
  เตือน 3 กรณี: ออเดอร์ใหม่เข้า, ลูกค้ากดเรียกพนักงาน และออเดอร์ค้างสถานะ "ใหม่" นานเกินกำหนด · ตั้งค่าที่แท็บ **แจ้งเตือน**
  เสียงกับจังหวะสั่นเป็นแบบเดียวทุกกรณี ตั้งค่าแยกไม่ได้ เพราะ Web Push เลือกไฟล์เสียงเองไม่ได้อยู่แล้วและ iPhone ไม่ฟังค่าที่เว็บสั่ง
- วันที่/เวลาเป็นภาษาไทย เวลาแบบ 24 ชั่วโมง ยึดเวลาไทย (Asia/Bangkok) เสมอ
- **ช่องเลือกวันที่เลือกตัวเลือกตามเครื่อง** (`components/DateField.js`) · เครื่องที่ใช้นิ้ว (มือถือ/แท็บเล็ต) ได้ตัวเลือกของระบบ
  ส่วนคอมได้ปฏิทิน flatpickr ภาษาไทยธีมมืด · ดูจาก `(pointer: coarse)` ไม่ใช่ขนาดจอหรือ user agent
  และโหลด flatpickr เฉพาะตอนใช้จริง เครื่องที่ใช้นิ้วจึงไม่ต้องดาวน์โหลดไลบรารีที่ไม่ได้ใช้

## สามโดเมน หนึ่งโค้ด (แยกด้วย middleware)

| โดเมน | หน้าที่ | ใครเข้า |
|---|---|---|
| `www.ful-fil.com` (และ `ful-fil.com`) | หน้าโชว์ร้าน: เมนูทั้งหมดแยกตามหมวด ของเล่น และรีวิวที่อนุมัติแล้ว | ใครก็ได้ · สั่งของไม่ได้ |
| `order.ful-fil.com` | หน้าสั่งของลูกค้า อันที่ QR ประจำโต๊ะชี้มา | ลูกค้าที่สแกน QR |
| `staff.ful-fil.com` | เว็บพนักงาน | พนักงานที่มี PIN |

ทั้งสามโดเมนใช้โค้ดชุดเดียวและ deploy ครั้งเดียว `middleware.js` ดูจากชื่อโดเมนแล้วส่งไปหน้าที่ถูกต้อง

**ตั้งค่าที่ Vercel** (Settings → Domains) เพิ่มทั้งสามโดเมนเข้าไปในโปรเจกต์เดียวกัน แล้วตั้ง DNS ตามที่ Vercel บอก
โดยทั่วไปคือโดเมนหลักใช้ `A` record ชี้ไปที่ Vercel ส่วน `www` / `order` / `staff` ใช้ `CNAME` ชี้ไป `cname.vercel-dns.com`

**เรื่อง QR ที่พิมพ์ไปแล้ว** ถ้ามี QR เก่าที่ชี้มาโดเมนหลัก ระบบจะเด้งไป `order.ful-fil.com` ให้อัตโนมัติพร้อมคีย์โต๊ะ ไม่ต้องพิมพ์ใหม่
ส่วน QR ที่สร้างใหม่จากเว็บพนักงานจะชี้ไป `order.ful-fil.com` ให้เองแล้ว (ถ้าโดเมนไม่ได้เป็นรูปแบบนี้ ให้ตั้ง `NEXT_PUBLIC_ORDER_ORIGIN`)

**ตอนรันในเครื่องหรือเปิดลิงก์พรีวิวของ Vercel** จะไม่แยกโดเมน เข้าตาม path ได้ทุกหน้า: `/` = หน้าสั่ง, `/staff` = พนักงาน, `/showcase` = หน้าโชว์

## อัปเดตทันทีทุกเครื่อง (Supabase Realtime)

หน้า **ต้องทำ** ต้องตรงกันทุกเครื่องตลอดเวลา ไม่งั้นพนักงานสองคนจะวิ่งไปทำงานเดียวกัน จึงใช้ Supabase Realtime

วิธีที่เลือกใช้คือ **ส่งแต่สัญญาณเปล่า ๆ ไม่ส่งข้อมูล**: เมื่อมีออเดอร์เข้า มีคนกดเรียก หรือมีคนปิดงาน
เซิร์ฟเวอร์จะยิงข้อความสั้น ๆ ว่า `changed` เข้าช่อง `fulfil-staff` แล้วเครื่องพนักงานค่อยไปดึงข้อมูลจริงผ่าน
`/api/dashboard` ที่ยังต้องมีโทเคนพนักงานเหมือนเดิม

ทำแบบนี้เพราะช่อง Realtime เป็นช่องสาธารณะ ใครมี anon key ก็เข้าฟังได้ ถ้าส่งเนื้อออเดอร์ไปกับช่องนี้
เท่ากับเปิดยอดขายให้คนนอกอ่าน · แบบนี้จึง **ไม่ต้องเปิด RLS ให้อ่านตารางไหนเลย และไม่ต้องรัน SQL เพิ่ม**

ตั้งค่า: ใส่ `NEXT_PUBLIC_SUPABASE_ANON_KEY` (หาได้ที่ Project Settings → API → `anon` `public`)
ถ้าไม่ใส่ ระบบยังทำงานได้ตามปกติ แค่เปลี่ยนไปดึงข้อมูลใหม่ทุก 5 วินาทีแทน (ช้ากว่านิดหน่อยเท่านั้น)

## ตั้งค่า Supabase (ทำครั้งเดียว)

1. สร้างโปรเจกต์ที่ https://supabase.com
2. ไปที่ **SQL Editor** วางเนื้อหาจากไฟล์ `supabase/schema.sql` แล้วกด Run เพื่อสร้างตารางทั้งหมด
3. ไปที่ **Project Settings → API** คัดลอกค่า:
   - `Project URL` ใส่ในตัวแปร `NEXT_PUBLIC_SUPABASE_URL`
   - `service_role` key (อยู่ใต้ Project API keys) ใส่ในตัวแปร `SUPABASE_SERVICE_ROLE_KEY` — เก็บเป็นความลับ ห้ามเปิดเผยฝั่ง client
   - `anon` `public` key ใส่ในตัวแปร `NEXT_PUBLIC_SUPABASE_ANON_KEY` — อันนี้เปิดเผยได้ ใช้สำหรับอัปเดตทันทีทุกเครื่อง

ดูตัวอย่างที่ `.env.local.example` ตอนรันในเครื่องให้คัดลอกเป็น `.env.local`

**ที่เก็บรูปเมนู/ของเล่นไม่ต้องไปตั้งเอง** ครั้งแรกที่อัปโหลดรูป ระบบจะสร้างถัง (bucket) ชื่อ `uploads` แบบ public ให้เองด้วย service role key
รูปเปิดอ่านได้สาธารณะเพราะลูกค้าดูเมนูโดยไม่ได้ล็อกอิน แต่**อัปโหลดได้เฉพาะ Manager ที่ล็อกอินแล้ว** (ผ่าน `/api/upload` เท่านั้น)

หมายเหตุ: ตารางเปิด Row Level Security ไว้และไม่มี policy ใด ๆ ฝั่ง anon จึงเข้าไม่ได้เลย
แอปเข้าถึงผ่าน service role key จากฝั่งเซิร์ฟเวอร์เท่านั้น ลูกค้าไม่ได้ยิงเข้า Supabase ตรง ๆ แต่ผ่าน API ของแอป

> **อัปเกรดจากเวอร์ชันก่อนหน้า** ให้รัน `supabase/schema.sql` ซ้ำอีกครั้ง (รันซ้ำได้ปลอดภัย ไม่ลบข้อมูลเดิม)
> **รอบล่าสุดเพิ่มตาราง `stock_items` กับ `stock_moves`** (ระบบสต็อก) — ไม่รันแล้วแท็บสต็อกจะใช้ไม่ได้
> ส่วนที่เหลือของรอบนี้ (เมนูย่อย, บิลเดี่ยว, รูปเมนู) **ไม่ต้องรัน SQL** เก็บใน `settings` กับ Storage หมดแล้ว
>
> รอบก่อนหน้าเพิ่มคอลัมน์ `reviews.approved` — ไม่รันแล้วหน้าเว็บโชว์จะไม่มีรีวิวขึ้นเลย
>
> รอบก่อนหน้าเพิ่มตาราง `service_calls` (ปุ่มเรียกพนักงาน) กับ `toys` (ของเล่น)
> ส่วนหมวดหมู่เมนูเก็บในตาราง `settings` เดิม ไม่ต้องแก้อะไรเพิ่ม
>
> รอบก่อนหน้าเพิ่มตาราง `staff`, `staff_sessions`, `shifts`, `activity_log`, `floor_items`,
> คอลัมน์ตำแหน่ง/สถานะของ `tables` และ `push_subscriptions.staff_id`
> **ถ้าไม่รันจะเข้าเว็บพนักงานไม่ได้เลย**

## เริ่มใช้เว็บพนักงาน (`/staff`)

1. รัน `supabase/schema.sql` เวอร์ชันล่าสุดก่อน
2. เปิด `https://โดเมนของคุณ/staff` ครั้งแรกจะให้ **ตั้ง Manager คนแรก** — ใส่ชื่อ, PIN 6 หลัก
   และยืนยันด้วย **รหัสผ่านหลังร้านเดิม** (ค่าเริ่มต้น `5429` ถ้าไม่เคยเปลี่ยน) หนึ่งครั้ง
3. เข้าระบบด้วยชื่อ + PIN แล้วไปแท็บ **พนักงาน** เพื่อเพิ่มคนอื่น (เลือกตำแหน่ง Staff หรือ Manager)
4. แนะนำให้ทุกคนกด **เพิ่มไปยังหน้าจอโฮม** แล้วเปิดจากไอคอนนั้น จะได้ทั้งเต็มจอและรับการแจ้งเตือนได้

## ตั้งค่าการแจ้งเตือน (Web Push)

การแจ้งเตือนใช้มาตรฐาน Web Push ของเบราว์เซอร์ **ฟรีและไม่จำกัดจำนวนข้อความ** ไม่ต้องพึ่ง LINE OA

### 1. ออกกุญแจ VAPID (ทำครั้งเดียว)

```bash
npm run vapid
```

จะได้ค่ามา 3 บรรทัด เอาไปใส่ที่ Vercel → Settings → Environment Variables แล้ว **Redeploy**:

- `NEXT_PUBLIC_VAPID_PUBLIC_KEY` — กุญแจสาธารณะ (ฝังไปกับหน้าเว็บ)
- `VAPID_PRIVATE_KEY` — กุญแจลับ **ห้ามเปิดเผย ห้าม commit**
- `VAPID_SUBJECT` — อีเมลติดต่อ เช่น `mailto:you@example.com`

> ออกกุญแจใหม่ทับของเดิมเมื่อไหร่ ทุกเครื่องที่เคยเปิดแจ้งเตือนไว้จะใช้ไม่ได้ทันที ต้องกดเปิดใหม่ทุกเครื่อง

### 2. เปิดการแจ้งเตือนทีละเครื่อง

เข้าหลังร้านจากเครื่องที่อยากให้เตือน → แท็บ **แจ้งเตือน** → **เปิดการแจ้งเตือนบนเครื่องนี้** → กดอนุญาต

- **Android / คอม**: กดได้เลยจากเบราว์เซอร์
- **iPhone / iPad**: ต้องเพิ่มลงหน้าจอโฮมก่อน (ข้อจำกัดของ Apple ไม่ใช่ของแอปนี้)
  1. เปิดเว็บใน **Safari** (Chrome บน iPhone ใช้ไม่ได้)
  2. กดปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม**
  3. เปิดแอปจาก **ไอคอนบนหน้าจอโฮม** เท่านั้น แล้วเข้าหลังร้าน กดเปิดการแจ้งเตือน

กดปุ่ม **ส่งทดสอบ** เพื่อเช็คว่าเด้งจริง

### 3. เปิดการเตือนออเดอร์ค้าง (ต้องตั้งเพิ่ม)

ออเดอร์ใหม่เตือนได้เองอยู่แล้ว แต่การเตือน "ออเดอร์ค้าง" ต้องมีตัวมาเรียกเป็นระยะ เพราะร้านอาจเงียบไม่มีใครเข้าเว็บเลย

1. ตั้ง Environment Variable `CRON_SECRET` บน Vercel เป็นข้อความอะไรก็ได้ที่เดายาก แล้ว Redeploy
   (ถ้าไม่ตั้ง ปลายทางนี้จะถูกปิดไว้ = ไม่มีการเตือนออเดอร์ค้าง)
2. สมัคร https://cron-job.org (ฟรี) แล้วสร้างงานใหม่:
   - URL: `https://โดเมนของคุณ/api/cron/stale-orders?secret=ค่าCRON_SECRET`
   - ความถี่: ทุก 1 นาที (ตอนเปิดหน้าต้องทำค้างไว้ ระบบตรวจเองอยู่แล้ว cron นี้เป็นตัวสำรองตอนไม่มีใครเปิด)
3. ปรับเวลาที่ถือว่า "ค้าง" ได้ที่แท็บ **แจ้งเตือน** (ค่าเริ่มต้น 10 นาที)

ออเดอร์หนึ่งใบจะถูกเตือนเรื่องค้างแค่ครั้งเดียว ไม่ตามตื๊อซ้ำ ๆ

### เกร็ด

- แตะที่การแจ้งเตือนจะเปิดแอปไปที่หน้าเข้าหลังร้านให้เลย (`/?admin=1`)
- เครื่องที่ลบแอป/ปิดสิทธิ์ไปแล้ว ระบบจะตัดออกจากรายการให้เองตอนส่งครั้งถัดไป
- ถ้าแจ้งเตือนเงียบหายโดยไม่รู้สาเหตุ ดู Logs ของโปรเจกต์บน Vercel จะมีบรรทัดขึ้นต้นด้วย `[push]`

## เริ่มใช้งานครั้งแรก

1. รัน `supabase/schema.sql` ใน SQL Editor ให้เรียบร้อยก่อน
2. เปิด `/staff` แล้วตั้ง Manager คนแรก (ดูหัวข้อด้านบน)
3. ไปแท็บ **ตั้งค่าร้าน → หมวดหมู่** จัดหมวดเมนูให้ตรงกับร้าน แล้วไปแท็บ **เมนู** กด **+ เพิ่มเมนู** ใส่รายการจริงเข้าไป
   (แท็บ **หมวดบัญชี** มีชุดตั้งต้นให้แล้ว แก้ทีหลังได้)
4. ไปแท็บ **ตั้งค่าร้าน → โต๊ะ + QR** กด **เพิ่มโต๊ะ** ให้ครบทุกโต๊ะ · จะเห็น QR ของแต่ละโต๊ะพร้อมปุ่ม **เซฟ QR** เอาไปพิมพ์แปะโต๊ะได้เลย
   ถ้า QR หลุดออกไปข้างนอกกดปุ่ม **ออกคีย์ใหม่** แล้วพิมพ์ใหม่ ของเดิมจะใช้ไม่ได้ทันที
5. ไปแท็บ **ผังโต๊ะ → แก้ไขผัง** ลากโต๊ะและกำแพงให้ตรงกับร้านจริง แล้วกดบันทึกผัง
6. จัดผังเสร็จแล้วกด **★ ตั้งเป็นผังตั้งต้น** หนึ่งครั้ง จากนั้นวันไหนโต๊ะถูกยกไปต่อกันจนเละ กด **คืนผังตั้งต้น** ก็กลับมาเหมือนเดิม

## ตารางข้อมูลใน Supabase

- `menu`: id, categories (text[] — หมวดทั้งหมดที่เมนูนี้อยู่), category (หมวดหลัก = หมวดแรก),
  name, price, image_url, active, sort_order, created_at
- `tables`: id, code, label, link, active, x, y, w, h, seats, status, status_at, reserved_name, reserved_at, merged_into
- `orders`: id, table_code, bill_table_code (โต๊ะหลักตอนต่อโต๊ะ), items (jsonb), total, status, created_at, stale_notified_at,
  payment_method (cash/transfer — เลือกตอนกดจ่ายแล้ว), paid_at
- `ledger`: id, date, kind (income/expense), category, item, cash, transfer, total, note, staff_id, staff_name, created_at
  (สมุดรายรับรายจ่ายที่ Manager กรอกเอง · `date` เป็น date ล้วนเพราะเป็นวันที่ตามบิล ไม่ใช่เวลาที่กดบันทึก)
- `staff`: id, name, role (manager/staff), pin_hash, pin_enc (สำเนา PIN แบบเข้ารหัส ไว้ให้เจ้าของร้านกดดู),
  active, sort_order, created_at
- `staff_sessions`: token, staff_id, created_at, expires_at
- `shifts`: id, staff_id, staff_name, started_at, ended_at (ว่าง = กำลังอยู่ในกะ)
- `activity_log`: id, staff_id, staff_name, role, action, detail, created_at
- `floor_items`: id, kind (wall/box/label), x, y, w, h, text, color, sort_order
- `reviews`: id, text, created_at
- `settings`: key, value (เก็บ hash ของ admin_password, เวลาที่ถือว่าออเดอร์ค้าง, หมวดเมนู, `ledger_categories` = หมวดบัญชี + ธงต้นทุนสินค้า,
  `notify_tab_hidden` = รายชื่อคนที่ถูกซ่อนแท็บแจ้งเตือน และ `floor_default` = ผังตั้งต้นของร้าน · ที่เป็นรายการเก็บเป็น JSON)
- `push_subscriptions`: endpoint, p256dh, auth, label, created_at, last_ok_at (หนึ่งแถว = หนึ่งเครื่องที่เปิดแจ้งเตือน)
- `stock_items`: id, name, unit, qty, low_threshold, active, sort_order, created_at
  (`qty` เป็น numeric ไม่ใช่ integer เพราะเมนูหนึ่งแก้วตัดเหล้าไป 45 มล. จากขวด 700 มล.)
- `stock_moves`: id, stock_id, delta, after_qty, reason (sale/restock/adjust), order_id, note, staff_id, staff_name, created_at
  (`order_id` ทำให้ออเดอร์ใบเดิมตัดสต็อกซ้ำไม่ได้ ต่อให้กดปุ่มเรียบร้อยรัวสองที)

**สิ่งที่เก็บใน `settings` แทนการเพิ่มคอลัมน์/ตารางใหม่** (ตั้งใจ เพราะทุกครั้งที่แตะ `schema.sql` เจ้าของร้านต้องไปรัน SQL เอง):
`menu_options` = กลุ่มเมนูย่อยของแต่ละเมนู · `menu_stock` = เมนูไหนตัดสินค้าอะไรบ้างเท่าไหร่ · `floor_default` = ผังตั้งต้น
ทั้งสามก้อนเป็น JSON ที่ key เป็น id ของเมนู · แลกกันตรงที่บันทึกทีละเมนูคือเขียนทับทั้งก้อน ซึ่งรับได้เพราะมี Manager แก้เมนูอยู่คนเดียว

**บิลเดี่ยว**ไม่มีคอลัมน์ของตัวเอง ใช้คีย์สงวน `walkin` ในช่อง `orders.table_code`
(ชนกับคีย์โต๊ะจริงไม่ได้เพราะ `genKey` สุ่มมา 16 ตัวอักษรเสมอ) · รายการนอกเมนูอยู่ใน `orders.items` โดยไม่มี `id` และติดธง `custom: true`

นอกจากตารางแล้วยังใช้ **Supabase Storage** ถัง `uploads` เก็บรูปที่อัปโหลดจากหลังร้าน
(`menu/<id>.jpg` และ `toy/<id>.jpg`) ในฐานข้อมูลเก็บแค่ลิงก์ไว้ที่ `menu.image_url` / `toys.image_url`
ตั้งชื่อไฟล์ใหม่ทุกครั้งที่อัปโหลด ไม่เขียนทับของเดิม เพราะ CDN แคชตามลิงก์ — เปลี่ยนรูปแล้วต้องเห็นรูปใหม่ทันที

## หมายเหตุด้านความปลอดภัย

สิ่งที่ระบบทำให้แล้ว:

- **ราคาคิดที่ฝั่งเซิร์ฟเวอร์เสมอ** ออเดอร์ที่ส่งเข้ามาจะถูกดึงราคาจากตาราง `menu` ตาม id ใหม่ทั้งหมด
  ราคา/ชื่อที่ client ส่งมาจะถูกทิ้ง แก้ราคาจากฝั่งลูกค้าไม่ได้
- **PIN ที่ใช้ตรวจตอนล็อกอินเก็บเป็น hash (scrypt)** ไม่ได้เก็บตัวเลขจริง · เปลี่ยน PIN / ปิดใช้งาน / เปลี่ยนตำแหน่ง = เตะเซสชันของคนนั้นออกทันที
  · ถ้าตั้ง `PIN_SECRET` ไว้ จะมี**สำเนา PIN แบบเข้ารหัส**อีกชุด (`staff.pin_enc`) ไว้ให้เจ้าของร้านกดดูตอนพนักงานลืม
  กุญแจอยู่ใน env ไม่ได้อยู่ในฐานข้อมูล · แลกกันตรงที่ ถ้าใครเข้าถึงได้ทั้งฐานข้อมูลและ env จะอ่าน PIN ของทุกคนได้
  ไม่อยากให้มีสำเนาเลยก็แค่ไม่ต้องตั้ง `PIN_SECRET` (ระบบทำงานปกติ แค่กดดู PIN ไม่ได้)
- **ล็อกอินแล้วได้ session token อายุ 12 ชั่วโมง** ไม่ต้องส่ง PIN ไปกับทุก request และเปิดแอปใหม่แล้วยังอยู่ต่อได้
- **ระบบไม่ยอมให้เหลือร้านที่ไม่มี Manager** ลดตำแหน่ง/ปิดใช้งาน/ลบ Manager คนสุดท้ายไม่ได้
- **จำกัดจำนวนครั้ง**: ใส่ PIN 10 ครั้ง/5 นาที, เปลี่ยน PIN ของตัวเอง 10 ครั้ง/10 นาที, สั่งออเดอร์ 20 ครั้ง/นาที,
  ส่งรีวิว 5 ครั้ง/นาที (ต่อ IP)
- **คีย์ประจำโต๊ะสุ่มด้วย crypto** ยาว 16 ตัวอักษร เดาไม่ได้
- จำกัดความยาว/ปริมาณของทุก input ที่เปิดให้คนนอกส่งเข้ามา

ข้อจำกัดที่ควรรู้:

- ตัวนับ rate limit เก็บในหน่วยความจำของแต่ละอินสแตนซ์ บน Vercel ที่สเกลหลายอินสแตนซ์จึงกันได้แบบ best-effort
  ด่านหลักที่กัน brute-force จริง ๆ คือ scrypt (ช้าโดยตั้งใจ) กับการที่คุณตั้งรหัสผ่านให้ยาวพอ
- ระบบนี้ออกแบบมาสำหรับใช้ภายในร้าน ถ้าต้องการมากกว่านี้ แนะนำต่อยอดเป็น Supabase Auth
  แล้วตั้ง RLS policy รายตารางแทนการใช้ service role key
